# 돈 규칙 (SAMEPLZ)

이 파일의 숫자는 와이어프레임 v0.5와 `docs/decisions.md`에서 왔다. 바꾸려면 결정부터 고친다. 결정이 open이면 구현을 멈추고 묻는다.

> **MVP(무료 출시)에는 실결제가 없다.** 이 규칙은 **크레딧 원장(grant·hold·settle)과 예산·한도 검사에만** 적용한다. 주문·쿠폰·수수료·로열티·환불·열기 전 7일·정산·체험은 **유료 전환 단계(사업자등록 후)**이고 MVP 코드에 넣지 않는다. 아래에서 「(유료 전환 단계)」가 붙은 절·줄이 그렇다.

## MVP 크레딧 (PLAY-04, PLAY-07, F4-14~16, D11·D12·D13)

- 크레딧은 **월 무료 지급뿐**이다. 로트 `kind = monthly_grant`(보너스 계열), 가입 때 그달 몫, 매월 리셋 때 새 로트. 양은 D11(월 270C, 하루 135C).
- 리셋 때 남은 몫은 `expire` 원장 행으로 소멸한다. 지급은 `(user, 월)` idem_key로 멱등이다.
- **유료 로트·충전·크레딧 환불 경로는 MVP에 없다.** `kind = paid` 로트를 만드는 코드가 있으면 안 된다.
- `start_run`은 홀드 전에 18+ 자기 확인, 계정 일일 한도(D11), IP·기기 레이트 리밋(D13), 전체 월 예산(D12)을 서버에서 검사하고, 하나라도 걸리면 아무것도 만들지 않는다(`DAILY_LIMIT`, `RATE_LIMITED`, `BUDGET_EXHAUSTED`).
- 예산은 홀드와 같은 트랜잭션에서 예약하고 `settle_cell`에서 실사용으로 맞춘다. 반환·안전 필터 차단은 예약을 되돌린다.
- 아래 「크레딧」 절의 홀드·정산·반환·불변식 규칙은 MVP에도 그대로 적용한다(충전·환불 줄만 유료 전환 단계).

## 크레딧 (PLAY-04, PLAY-07, CRD-01~04, m:charge, m:crRefund)

- 크레딧 단위는 D17: 내부 기준 1C ≈ 3.7원. 화면에 원화 환산을 쓰지 않고, 실행 전 견적(크레딧 수)은 반드시 보여 준다. (유료 전환 단계) 충전 팩은 결제 화면에 총액(원)을 먼저 보여 준다.
- (유료 전환 단계) 충전 팩 구성은 D17 단위로 유료 전환 때 D3와 함께 다시 정한다(이전안: 5,000원=500C, 10,000원=1,050C, 30,000원=3,300C — 1C=10원 기준이라 그대로 쓰지 않는다).
- 사용 순서는 보너스 로트가 먼저, 만료가 가까운 로트가 먼저여야 한다.
- 보너스 크레딧(MVP의 `monthly_grant` 포함)은 환불하지 않으며 유료로 바뀌지 않아야 한다.
- 모델 오류는 같은 로트로 반환해야 한다(내역 「반환」). 안전 필터 차단은 차감하지 않아야 한다.
- 셀마다 정산은 정확히 한 번이어야 한다(`settle_cell`, 두 번째부터 noop).
- 크레딧으로 레시피를 살 수 없어야 한다(PLAY-07, PAY rl). 크레딧은 자체 생성에만 쓴다(D3 면제 5원칙).
- (유료 전환 단계) 유료 크레딧 환불: 결제 후 7일 안 미사용분 전액, 이후 미사용 유료분은 10% 이하 공제(D3, 카드 수수료 별도 공제 금지). 진행 중 홀드는 환불 대상에서 뺀다.
- `credit_accounts.available >= 0`, `held >= 0`. 원장 합은 계정 잔액과 같아야 한다.
- 견적에 `price_version`을 싣고 실행 때 바뀌었으면 409로 거절한다(F4-1).

## 유입·수수료·로열티 (PAY-02, PAY-05, SELL-02, SELL-04, D1) — 유료 전환 단계

MVP: 공유 링크는 유입 수만 센다(수수료·귀속 없음). 포크는 원작 표시만.


- 직접 유입 수수료 5%(500bps), 마켓 유입 15%(1500bps).
- 직접 유입은 공유 링크 클릭 뒤 7일 안의 마지막 클릭이고, 구매자 ≠ 크리에이터(user·CI·기기)일 때만이다.
- 크리에이터 쿠폰은 그 크리에이터 레시피에만 적용되고, 쿠폰을 쓰면 직접 유입이다.
- 포크 판매 시 원작자 로열티 10%(1000bps)는 **포크 판매자 몫에서 차감**, **결제액(쿠폰 후) 기준**, **직계 원작만**이다(D1 권고, 결정 전이면 멈춤).
- 유입·수수료율·로열티·금액은 주문 행에 동결하고 다시 계산하지 않는다. 클라이언트가 보낸 금액은 쓰지 않는다(`get_checkout_quote`).
- 가격은 0원(무료) 또는 1,000원 이상이다(UP-06).

## 환불·열기 (LIB-02, LIB-04, PAY-03, m:openConfirm, m:refund) — 유료 전환 단계

MVP: 확인 팝업 없이 원문을 열고 `opened_at`은 통계용으로만 기록한다(D6).


- 환불은 `now() < paid_at + 7 days AND opened_at IS NULL`일 때만이다. 판정은 DB 함수(`refund_order`)가 한다.
- 열기(`open_original`)와 환불은 같은 권리 행을 `FOR UPDATE`로 잠가 하나만 성공해야 한다.
- 열어 본 뒤에는 환불 대신 「설명과 달라요」 신고(3개월)다.
- PG 취소는 큐에 쌓지 않고 즉시 호출한다(3영업일 안 환불).
- 필수 동의 2개 전에는 결제할 수 없다. 주문에 동의 문구 버전·시각·`trial_available`을 저장한다.
- 부분 환불, 가상계좌·계좌이체는 출시 범위 밖이다.

## 정산 (SELL-05, D2, D7) — 유료 전환 단계

- `hold_until = paid_at + 7 days`. 열린 환불·신고가 있으면 보류를 풀지 않는다.
- 화요일 배치 → 수요일 지급(토스페이먼츠 지급대행, 요청당 100건 이하).
- 원천징수율은 `seller_profiles.withholding_rate_bp`에서 읽는다. 3.3%를 코드에 박지 않는다(D2).
- 지급 뒤 환불분은 음수 행(`refund_reversal`)으로 남기고 다음 정산에서 상계한다. 지운 행은 없다.
- 내 계좌로 받아서 나눠 주는 구조는 금지다(지급대행만).

## 체험 (PLAY-01, D6) — 유료 전환 단계

MVP: 체험 모드 없음(D6 closed). 원문 서버 렌더링 규칙은 모든 실행에 적용(hidden-content).


- 체험은 안 받은 유료 레시피에 사용자당 1회(`trial_uses` PK(user, recipe)), 무료, 출시 때 이미지 모델만, 셀 3개 × 1장 상한.
- 체험 결과는 서버에서 워터마크를 박고 원본은 저장하지 않는다. 원문은 서버 밖으로 나가지 않는다.

## 보관

- (유료 전환 단계) 주문·정산 기록은 5년, 분쟁 기록은 3년 분리 보관(`archive.*`). 탈퇴는 익명화 soft delete(MVP에도 적용).
- 탈퇴 1년 뒤 그 회원의 원장·로트·계정·동의 행은 `private.purge_withdrawn_members()`만 지울 수 있다(D22). 이것이 원장 DELETE 금지의 유일한 예외이고, 홀드는 예산 대사를 위해 남긴다. 활동 회원의 원장 행은 어떤 경로로도 지우지 않는다.

## 결제 수단·키 — 유료 전환 단계

- 결제 확인은 확인 API + Idempotency-Key(= 주문 id). 웹훅은 힌트로만 쓰고 상태를 다시 조회한다.
- 같은 이벤트 재수신은 no-op(`pg_payment_key`, `event_key` unique).
