# 스프린트 상태

> sprint-flow 플러그인의 같은 이름 스킬을 저장소로 복사한 것이다(클라우드 세션은 저장소에 선언한 플러그인을 설치하지 않는다). 플러그인 쪽을 고치면 이 파일도 맞춘다.

## 읽을 것

- `docs/plan-12w.md` — **7주 MVP 계획**(파일 이름만 12w). 오늘 날짜로 주차를 구한다(W1 = 2026-10-05 월요일 시작, 주는 월~일, 출시 W7 = 11/16~11/22). 그 주의 개발·외부 일정·콘텐츠·게이트. W7 이후면 「유료 전환 단계」 절을 본다.
- `docs/features.json` — **`"phase": "paid"`가 아닌 항목만** 센다: 통과 수/전체, 이번 주까지 목표(`week <= 현재 주`)인데 `passes: false`인 항목. paid 항목 수는 「유료 전환 단계 N개 제외」로만 적는다.
- `docs/decisions.md` — 상태 open인 결정과 기한(`deferred (유료 전환 단계)`·`closed`는 빼고). 기한 주가 지났거나 이번 주면 강조.
- `docs/progress.md` — 마지막 10줄.
- `git log --oneline -10`, 현재 브랜치, `gh pr list --author @me --state open`(있으면).

## 출력 (짧게)

```
W<n> (MM/DD~MM/DD) · 출시까지 <n>주
이번 주 게이트: …
외부 일정(임계 경로): …
기능: <통과>/<전체(paid 제외)> (유료 전환 단계 <n>개 제외) · 이번 주까지 미통과: <ID 목록>
막힌 결정: D<n> <이름> (기한 W<n>) …
다음 작업: <가장 이른 미통과 항목 또는 현재 브랜치 계획의 다음 체크박스>
잘라 낼 후보(일정이 밀리면): docs/plan-12w.md "잘라 낼 순서"의 다음 항목
```

판단을 덧붙이지 말고 파일에 있는 사실만 요약한다. 일정이 밀렸으면 몇 개 항목이 몇 주 밀렸는지만 적는다.
