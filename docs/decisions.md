# 착공 전 결정 (D1~D15)

이 결정들이 `orders`·`seller_earnings`·`credit_lots`의 컬럼과 약관 문구를 정한다. 코드보다 먼저 닫는다.

> **MVP(무료 출시, 2026-10-06 범위 변경)**: 사업자등록 전이라 PG·통신판매업·본인인증이 없다. 결제·정산·판매자 신원에 걸린 D1·D2·D3·D7·D9는 `deferred (유료 전환 단계)`로 미뤘다(훅은 open만 보여 주므로 세션 컨텍스트에 안 뜬다). MVP의 비용·남용 결정은 D11~D13으로 새로 연다. 일정은 `docs/plan-12w.md`(7주 MVP).

- 상태는 `open` / `closed` / `deferred (유료 전환 단계)` 중 하나. 닫을 때는 아래 요약 표의 상태를 `closed`로 바꾸고, 본문의 "결정" 줄에 날짜·선택·근거 한 줄을 적는다.
- SessionStart 훅(`.claude/hooks/session-context.sh`)이 요약 표에서 `open`인 줄을 읽어 세션마다 보여 준다. **요약 표의 열 순서(ID · 결정 · 확인 주체 · 기한 · 상태)를 바꾸지 않는다.**
- Claude는 open 결정이 막는 작업을 추측으로 진행하지 않는다. 멈추고 묻는다.

## D1 · 포크 로열티 10%는 누가 내고, 어떤 금액 기준인가

- **선택지**: A 포크 판매자 몫에서 추가 차감 / B 플랫폼 수수료에서 지급 / C 정가에 가산. 기준은 정가 또는 쿠폰 후 결제액. 대상은 직계 원작 또는 전체 계보.
- **권고**: **A + 결제액 기준 + 직계 원작만.** B는 직접 유입 수수료(5%)가 로열티(10%)보다 작아 건마다 적자다. 계산한 숫자는 주문 행에 동결한다.
- **예시**: 1만원 포크 레시피가 마켓 유입으로 팔리면 플랫폼 1,500원, 원작자 1,000원, 포크 판매자 7,500원(원천징수 전). 직접 유입 + 쿠폰 2,000원으로 8,000원 결제 시 플랫폼 400원, 원작자 800원, 판매자 6,800원.
- **영향**: `orders.fork_royalty_bps`·`fork_royalty_to`, `seller_earnings.kind = fork_royalty`, 판매자 약관.
- **확인 주체 · 기한**: 창업자 → 약관(변호사) · 유료 전환 단계
- **상태**: deferred (유료 전환 단계) — MVP에는 판매가 없어 로열티가 생기지 않는다. 포크는 원작 표시만 한다.

## D2 · 개인 판매자 소득을 어떻게 처리하나

- **선택지**: A 개인은 사업소득 3.3% 일괄(와이어프레임) / B 판매자별 구분(사업자·사업소득 3.3%·기타소득 8.8%) / C 사업자만 판매.
- **권고**: **B, 기본값은 사업소득.** `income_type`·`withholding_rate_bp`를 설정값으로 두고 3.3%를 코드에 박지 않는다.
- **근거**: 3.3%는 계속적·반복적 인적용역, 8.8%는 일시적·우발적 소득에 맞는 구분. 기타소득은 건당 125,000원 이하면 과세가 없는 대신 간이지급명세서를 매달 낸다. 디지털 상품 판매는 재화·전자적 용역 공급일 수 있고, 그러면 판매자는 사업자등록·부가세 대상이 되며 플랫폼은 2025년 7월부터 판매자별 거래 내역을 분기마다 국세청에 낸다. 2027년 지급분부터 3.3% → 2.2% 개정안이 계류 중이라 원천징수율은 설정값이어야 한다.
- **영향**: `seller_profiles.income_type`, `withholding_rate_bp`, `payouts.withholding_income/local`, `tax_exports`, m:verify 문구.
- **확인 주체 · 기한**: 세무사 · 유료 전환 단계(첫 지급 전)
- **상태**: deferred (유료 전환 단계) — MVP에는 판매·지급이 없어 판매자 소득이 생기지 않는다.

## D3 · 크레딧을 선불전자지급수단 면제 범위에 두는 조건과 환불 규칙

- **선택지**: 환불 수수료 0% / 10% 이하 / 카드 수수료 별도 공제. 탈퇴 시 유료 크레딧 소멸 여부.
- **권고**: **면제 5원칙 고정** — ① 자체 생성에만 사용 ② 레시피·크리에이터 결제 불가 ③ 양도 불가 ④ 원 결제수단 환불만 ⑤ 제휴 서비스 사용 불가. 7일 안 미사용분은 전액, 이후 미사용 유료분은 10% 이하 공제(카드 수수료 별도 공제 금지). 유료분 유효기간 5년, 보너스는 유효기간을 명시하고 환불하지 않는다. 탈퇴 전에 유료분 환불을 거치게 한다.
- **근거**: 2024년 9월 개정으로 면제 요건이 "1개 가맹점에서만 사용"으로 좁아졌고, 제3자 판매자 상품을 살 수 있는 크레딧은 등록 대상(위반 시 5년 이하 징역 또는 3억원 이하 벌금). 환불 수수료 10%는 공정위가 다른 업종 약관 시정에서 받아들인 수준. 환불 시 카드 수수료를 따로 떼는 조항은 불공정 약관으로 판단됨.
- **영향**: `credit_lots.kind`·`expires_at`, `request_paid_refund` 공식, m:charge·m:crRefund·m:withdraw 문구, GUIDE-04.
- **확인 주체 · 기한**: 변호사 · 유료 전환 단계(충전 열기 전)
- **상태**: deferred (유료 전환 단계) — MVP 크레딧은 판매하지 않는 월 무료 지급(보너스 계열)뿐이라 충전·환불 규칙이 아직 필요 없다.

- **확인 주체 · 기한**: 창업자(MVP) → 변호사(유료 전환) · W1

## D6 · 체험 비용과 '열기'의 정의

- **선택지**: 체험 무료 / 크레딧 차감. 받은 레시피를 플레이그라운드에서 돌리면 열람인가.
- **MVP 선택**: **체험 모드 없음.** 모든 레시피가 무료라 받은 뒤 월 무료 크레딧 한도 안에서 실행한다. 환불이 없으니 m:openConfirm·「열어 봄 · 환불 제한」도 없다. `opened_at`은 통계용으로만 기록한다.
- **유료 전환 때 다시 볼 것**: 이전 권고(체험 무료, 이미지 모델만, 셀 3개 × 1장, 「원문 보기·편집」 때만 m:openConfirm)를 유료 레시피에 다시 적용할지.
- **영향**: `trial_uses` 테이블은 MVP에서 만들지 않음, `start_run` 모드 판정(내 레시피·받은 무료 레시피·빈 프롬프트), `opened_at` 기록 지점.
- **확인 주체 · 기한**: 창업자 · W1
- **상태**: closed
- **결정**: 2026-10-06 · 체험 없음, 월 무료 크레딧 한도 안에서 무료 실행 · 전부 무료라 체험이 필요 없고 환불 판정도 없다.

## D15 · 레시피 검색 구현 방식

- **선택지**: A RLS가 걸린 `recipes`에 PGroonga `&@~`를 직접 건다 / B 공개 조건을 함수 안에 직접 넣은 SECURITY DEFINER `search_recipes` RPC로만 검색한다
- **근거(스파이크 `docs/spikes/W1-pgroonga-korean.md`, 2만 행)**: A는 PGroonga 연산자가 LEAKPROOF가 아니라 RLS 조건보다 먼저 인덱스로 못 쓰여 Seq Scan **2,366ms**. B는 인덱스 스캔 **9~19ms**. F1-5 세 단어는 두 방식 모두 정확히 걸림.
- **영향**: 검색은 `public.search_recipes`만(직접 `&@~` 금지), 입력은 `pgroonga_query_escape`, 실행 권한 `anon`·`authenticated`, 반환은 공개 필드 DTO. `create extension pgroonga with schema extensions`. 이 함수만 `search_path = extensions, public` 예외(`pgroonga_condition()`이 `''`에서 동작하지 않음, 돈 RPC 아님).
