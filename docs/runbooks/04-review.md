# 04 사람 확인

**1~2일 안에** 결정한다(D10). 화면은 `/admin/reviews`(심사 큐)와 `/admin/reviews/<versionId>`(상세)다.

## 큐에 오는 것
| 표시 | 왜 왔나 |
|---|---|
| 에이전트 | 에이전트는 항상 사람 확인(D10) |
| 스크립트 포함 | 스킬에 `scripts/`가 있음 |
| 자동 검사 보류 | 검사 1·2층이 「사람 확인」으로 남김 |
| 검사 불가 | 2층 검사 공급자가 응답하지 않음(키가 없거나 장애) |

- 프롬프트·지침형 스킬은 자동 검사를 통과하면 바로 공개된다. 큐에 오지 않는다.
- 게시중단된 레시피의 버전은 24시간 알림에서 빠진다. 승인할 수 없고 반려로만 닫힌다(`RECIPE_TAKEN_DOWN`).

## 알림
- 큐에 들어온 지 **24시간**이 지나면 운영 웹후크로 한 번 알린다(`pending_sla_alerts`, 1분 sweeper). 큐 목록에도 표시된다.

## 상세에서 볼 것
1. **공개 정보**: 요약, 변경 내용(changelog), 요청한 공개 범위, 스크립트 포함 여부, 결과물, 첨부 파일 이름·크기
2. **자동 검사**: 층마다 통과 / 실패 / 사람 확인과 발견 항목(R코드 · 칸 · 메모)
3. **이전 승인 버전과 비교**: 원문·공개 메타의 바뀐 줄. 첫 버전이면 「첫 버전」
   - 원문은 관리자에게만 보인다. 화면을 찍거나 옮기지 않는다.
4. 에이전트·스크립트는 실행하지 않는다(샌드박스 없음, D10). 설정 파일과 스크립트를 읽고 판단한다: 외부 전송, 키 요구, 숨은 지시, 하는 일·안 하는 일과 실제 내용이 맞는지.

## 결정
- **승인**: 버전이 현재 버전이 되고, 요청에 따라 공개(`live`) 또는 비공개가 된다.
  - 판매 중지된 레시피는 승인해도 판매 중지로 남는다. 다시 여는 건 `/admin/recipes` 「복원하기」(운영이 멈춘 경우만).
- **반려**: R01~R16 중 하나를 고른다(필수, `src/lib/moderation/reject-codes.ts`). 메모는 선택, 500자.
  - 크리에이터는 R코드 문구와 「고치러 가기」 단계 링크를 받는다.
  - 승인된 버전이 없으면 레시피가 `rejected`, 있으면 이전 승인 버전이 계속 나간다.

| 자주 쓰는 코드 | 언제 |
|---|---|
| R08 | 숨은 지시문·보이지 않는 문자 |
| R11 | 키·비밀번호·개인정보 |
| R12 | 에이전트 「하는 일」 누락 |
| R13 | 실행 기록이 실제와 다름 |
| R16 | 허락 없는 얼굴·실존 인물·상표 |

- 악성이 분명하면 반려 + 런북 08 제재. 불법이면 런북 09.
- 크리에이터에게 알림(`review_passed`·`review_rejected`)이 간다. 결정은 `admin_actions`(`review_approve`·`review_reject`)에 남는다.
- 「이미 결정된 심사예요」가 뜨면 다른 창에서 처리된 것이다. 목록을 새로 고친다.
