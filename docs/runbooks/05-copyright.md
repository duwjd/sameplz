# 05 저작권

흐름: **접수 → 게시중단 → 게시자 통지 → 소명 받기 → 복원(또는 유지) → 반복 침해자 처리.** 법정 절차와 기한은 저작권법 제103조와 시행령을 따른다. 처리 전에 현행 조문(특히 재개 요구 뒤 복원 시점)을 확인한다.

## 1. 접수
- 앱 안: 신고 사유 「남의 결과물」(`rights`) → `/admin/reports`
- 앱 밖: 고객센터 메일(`src/lib/policy/operator.ts`의 `CONTACT_EMAIL`)
- 받을 것: 권리자 이름·연락처, 침해 레시피 주소(`/r/<공개 ID>`), 원저작물과 권리 소명 자료, 침해 내용. 빠지면 보완을 요청한다.

## 2. 게시중단
- 권리 소명이 있으면 지체 없이 내린다.
  - 신고함에서: 결정 「레시피 게시중단」, 사유 「권리 침해 신고」(`rights_claim`)
  - 메일 접수: `/admin/recipes`에서 공개 ID나 제목으로 찾기 → 「게시중단하기」 → 사유 `rights_claim`
- 결과: 상세·검색·갤러리에서 사라지고, 받은 사람도 원문·파일·업데이트를 쓸 수 없다. 결과물은 비공개 버킷으로 옮겨진다(D18). 새 버전 제출·승인도 막힌다.
- 판매 중지로 충분한 사안(예: 일부 결과물만 문제)인지 먼저 본다. 차이는 런북 06.

## 3. 게시자 통지
- **자동**이다. 게시중단하면 크리에이터에게 알림 `recipe_taken_down`(「사유: 권리 침해 신고가 들어와 확인하고 있어요. … 이의는 고객센터로 알려 주세요.」)이 간다.
- 권리자에게는 신고 답변(앱 안) 또는 메일로 중단 사실을 알린다.

## 4. 소명 받기
- 크리에이터가 고객센터 메일로 소명(정당한 권리 자료)을 보내면 받는다. 앱 안 소명 화면은 MVP에 없다.
- 소명을 받으면 권리자에게 재개 예정을 알리고, 법정 기한에 맞춰 복원한다(기한은 위 조문 확인).
- 소명이 없거나 근거가 약하면 게시중단을 유지한다.

## 5. 복원
- `/admin/recipes` → 「복원하기」, 메모 필수.
- **게시중단 직전 상태 그대로** 돌아간다(공개·판매 중지·비공개·심사 중). 비공개거나 크리에이터가 멈춘 레시피가 운영 조치로 공개되지 않는다.
- 크리에이터에게 「게시중단을 풀었어요」 알림이 간다. 받은 사람은 다시 쓴다.

## 6. 반복 침해자
- 권리 침해가 확인되면 크리에이터에게 런북 08 제재를 건다(권장: 1회 확인 → 판매 정지, 반복 → 계정 정지 → 차단). 제재 사유는 「권리 침해」(`rights_claim`).
- 확인 이력은 `admin_actions`(`recipe_takedown`, `reason = rights_claim`)와 `/admin/users/<id>` 제재 이력으로 본다.

## 명예훼손·사생활
저작권이 아니라 정보통신망법 임시조치(최대 30일)다. 런북 09.
