# 07 사기·남용 (MVP: 무료 크레딧)

MVP에서 돈이 새는 곳은 무료 생성이다. 사용자는 돈을 내지 않고, 공급자 비용만 나간다(D11·D12·D13).

## 자동으로 막히는 것 (손대지 않아도 됨)
- 실행 횟수: 분당 5회(사용자·IP·기기 각각), 하루 135C(D11)
- 가입: IP당 하루 3개. 같은 기기의 두 번째 계정부터는 그달 무료 크레딧이 나가지 않는다(`abuse_signals.shared_device_grant`).
- 안전 필터: 24시간 안에 차단 3회면 생성이 멈춘다(`credit_accounts.generation_suspended_at`).
- 월 예산: 80%·100%에 운영 웹후크로 알린다. 100%면 킬 스위치가 실행을 막는다(D12).

## 사람이 볼 때
1. **알림이 오면**: 운영 채널의 웹후크(예산·SLA)를 본다. 아니면 `/admin/users/<id>`의 「최근 남용 신호」를 본다.
2. **연결 계정**: `/admin/users/<id>` 「연결 계정」에서 같은 기기나 같은 IP로 쓴 계정을 본다.
   - **확률적 판단이다.** CI(본인인증)가 없어서다(D13). 같은 IP는 회사·카페·가족 와이파이일 수 있고, 같은 기기는 가족이 같이 쓰는 PC일 수 있다.
   - 연결만으로 제재하지 않는다. 짧은 간격의 가입, 같은 시간대 한도 소진, 같은 프롬프트 패턴처럼 다른 근거가 함께 있을 때 판단한다.
3. **생성이 자동으로 멈춘 회원**
   - 결과 기록(`play_cells` 차단 사유)을 본다.
   - 오탐이면 「생성 다시 열기」를 누르고 이유를 적는다.
   - 의도적이면 런북 08의 제재로 넘어간다.
4. **크레딧 조정**: 오류 보상이나 이벤트는 「크레딧 조정하기」(±1000C, 사유는 회원 알림에 보인다)로 한다.
   - 더한 크레딧은 그달 리셋 때 같이 사라진다.
   - 빼기는 회원이 지금 쓸 수 있는 몫 안에서만 된다.

## 기록
모든 조치는 `admin_actions`에 남는다. Studio에서 직접 고치면 같은 내용을 `admin_actions`에 손으로 남긴다.
