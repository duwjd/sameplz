# 11 개인정보 사고

유출·분실·무단 접근이 의심되면 바로 시작한다. 연락처·보호책임자는 `src/lib/policy/operator.ts`(`PRIVACY_OFFICER`, `CONTACT_EMAIL`)다.

## 가진 개인정보 (`/privacy` 기준)
| 종류 | 어디 | 메모 |
|---|---|---|
| 로그인 식별자, 이메일(Google·네이버만), 이름·닉네임, 프로필 사진 | Supabase Auth, `profiles` | 카카오는 이메일 없음, 네이버는 자리표시 이메일 |
| 동의·만 18세 확인 시각, 문구 버전 | `consent_events`, `profiles` | |
| 핸들·소개·직무 | `profiles` | 선택 |
| 받은·올린 레시피, 결과물, 플레이그라운드 프롬프트·레퍼런스·결과물, SAME 인증·좋아요·팔로우·신고, 크레딧 기록, 알림 | DB, Storage | 레퍼런스(얼굴 포함) 24시간, 프롬프트 기록 30일 뒤 삭제 |
| IP·기기 쿠키(`sp_did`) | `account_devices`, `abuse_signals`, `rate_limit_buckets` 등 | **서버 비밀 키 HMAC 해시만.** 원래 값은 없다 |

- 주민등록번호·결제 정보는 없다.
- 레시피 원문·프롬프트·공급자 응답은 로그·DTO·Realtime에 싣지 않는다(절대 규칙 7). Sentry에도 보내지 않는다.

## 순서
1. **막기 (즉시)**
   - 새는 경로를 끊는다: 문제 기능 배포 되돌리기(런북 10), 키 교체(`SUPABASE_SECRET_KEY`, 공급자 키, `CRON_SECRET`), 의심 관리자 권한 회수(런북 12).
   - 공개 버킷에 잘못 나간 파일은 게시중단·숨김으로 비공개 버킷으로 옮긴다.
   - 증거를 남긴다: 시각, 범위, Vercel·Supabase 로그(Free는 7일 보관이라 바로 받아 둔다).
2. **평가**
   - 어떤 항목이, 몇 명분, 언제부터 언제까지, 누구에게 나갔나. 해시만 나갔는지, 원래 값이 나갔는지.
   - 원인: 코드 결함, RLS 누락, 키 노출, 계정 탈취, 외부 공격(해킹).
3. **신고·통지**
   - **정보주체 통지**: 유출을 알게 되면 원칙적으로 **72시간 안에** 해당 회원에게 알린다(항목, 시점·경위, 피해 줄이는 방법, 대응, 연락처). 연락처가 없는 회원(카카오)은 서비스 안 알림·공지로 한다.
   - **개인정보보호위원회(또는 KISA) 신고**: **1천 명 이상 또는 민감정보·고유식별정보·해킹 등 법정 요건에 해당하면** 72시간 안에 신고한다.
   - 기한과 요건은 개인정보보호법 제34조·시행령을 기준으로 하되, 사고 때 **현행 법령을 다시 확인**한다.
4. **고치기**: forward-fix 마이그레이션·코드 수정, security-auditor 감사, 재발 방지 테스트(pgTAP·e2e).
5. **기록**: 경위·조치·통지 내용을 남긴다. DB를 손으로 고쳤으면 `admin_actions`에 수기 기록(런북 12).
