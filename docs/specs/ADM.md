# ADM · 운영 (와이어프레임 밖)

- 경로: `/admin/**` (admin 클레임 + MFA, noindex)
- 기능 묶음: [F8](F8-operations.md) — F8 운영 — ADM · 분석 · 관측 (와이어프레임 밖)
- 와이어프레임에 화면 코드가 없다. 디자인은 디자인 시스템의 Table·Form 기본형으로 충분하다.

> **MVP 범위 F8-4**(W7, 2026-10-16): `/admin/users`(id·핸들·닉네임으로 찾기)·`/admin/users/[id]`(제재 이력, 크레딧 요약과 최근 원장, 연결 계정). 제재 사다리(경고 → 판매 정지 → 계정 정지 → 차단, 약관 제6조)는 **관리자가 단계를 고르고 자동 승급은 없다**(사용자 결정). 판매 정지는 새 레시피·새 버전만, 계정 정지는 받기·만들기·올리기·글쓰기(팔로우·좋아요·SAME 인증·신고·대기 명단 포함)를 막고 받은 레시피 열기는 둔다, 차단은 계정 정지 + 로그아웃 + `/blocked` + 월 무료 지급 중단. 막는 곳은 쓰기 테이블의 BEFORE INSERT 가드(`private.guard_sanctioned_actor`)와 `check_run_allowed`(`ACCOUNT_SUSPENDED`) — RLS·RPC 어느 길로 와도 같다. 기간이 끝나면 계산으로 풀린다(cron 없음). 제재는 고치지 않고 한 번 해제만 한다. 멈춘 생성(차단 3회, D13) 다시 열기, 크레딧 조정(±1000C, +는 그달 리셋 때 사라지는 promo 로트, −는 쓸 수 있는 몫에서만, 멱등) — 모두 사유 필수, `admin_actions`, 회원 알림. 연결 계정은 같은 기기·IP 해시(가입·로그인·실행 때 기록)로 보이고 확률적 판단이다(런북 07). **뺀 것**: CI 기반 연결 계정·주문 조회·환불 예외·지급 모니터(유료 전환 단계), JWT `admin` 클레임·MFA(D23, 출시 뒤).

> **MVP 범위**(W6, 2026-10-15): `/admin`(개요)·`/admin/reviews`(심사 큐·상세: 자동 검사·결과물·이전 승인 버전과의 원문·공개 메타 diff, 승인 / R01~R16 반려 템플릿)·`/admin/reports`(사유·대상·신고자의 받은 시각·열람 시각, 결정 = 기각·판매 중지·게시중단·글 숨김, 답변 필수 → 같은 대상의 열린 신고가 함께 닫히고 신고자마다 알림)·`/admin/recipes`(판매 중지·게시중단·복원). 관리자 판정은 서버가 `profiles.role = 'admin'`으로 하고(사용자 결정), 관리 RPC는 service_role 전용으로 역할을 다시 확인하고 사유와 함께 `admin_actions`에 남긴다. 게시중단(`taken_down`)은 받은 사람도 원문·파일·업데이트를 쓸 수 없고 관리자 「복원」만 풀 수 있다(게시중단 직전 상태로 돌아간다 — 비공개·크리에이터가 멈춘 레시피가 운영 조치로 공개되지 않는다). 게시중단 중에는 새 버전 승인도 막는다. 24시간 넘은 심사·20시간 무응답 신고는 운영 웹후크(`OPS_ALERT_WEBHOOK_URL`)로 한 번씩 알린다. **뺀 것**: JWT `admin` 클레임 훅과 MFA(F8-4, W7), 소명 요청, 환불·제재(유료 전환·F8-4), 저작권 복원 요청 화면(관리자가 「복원」으로 수동 처리), 명예훼손·사생활 임시조치 30일 자동 만료(수동).

## 목적

와이어프레임에는 운영 화면 코드가 없지만, 심사 1~2일과 신고 첫 답 1영업일 규칙을 지키려면 운영 화면이 출시 때 있어야 한다. Retool은 감사 로그와 세부 권한이 Business 요금제(빌더당 월 50달러)부터라 같은 Next.js 앱 안에 `/admin`을 만든다. 권한은 커스텀 액세스 토큰 훅으로 JWT에 넣은 `admin` 클레임과 RLS의 `authorize()`로 판정한다. Supabase Studio는 비상용으로만 쓴다(Studio에서 고친 내용은 앱 감사 로그와 알림을 건너뛴다).

## 아이템

- **ADM-심사 큐**: 자동 검사 결과, 이전 버전 diff, 승인·반려(R01~R16 템플릿), 24시간 경과 알림
- **ADM-신고함**: 사유 4종, 열람 시각·구매 이력, 소명 요청, 결정(기각·환불·판매 중지·게시중단·제재), 20시간 무응답 알림
- **ADM-판매 중지/게시중단**: 판매 중지는 받은 사람 계속 사용, 게시중단은 모두에게 숨김. 저작권: 접수 → 즉시 중단 → 게시자 통지 → 복원 요청 → 복원
- **ADM-주문·크레딧·지급**: 주문 조회·환불 예외, 크레딧 조정(`adjust` 반대 행), 지급 모니터(화요일 미리보기·보류 플래그)
- **ADM-제재**: 경고 → 판매 정지 → 계정 정지 → 차단, 연결 계정(CI·기기·IP)

## 규칙

- 모든 조치는 사유 필수, `admin_actions`에 insert만(수정·삭제 트리거로 거부).
- Supabase Studio는 비상용. Studio에서 고친 내용은 감사 로그·알림을 건너뛰므로, 썼다면 `admin_actions`에 수기 기록.
- 판정은 JWT `admin` 클레임 + `private.is_admin()`. `user_metadata` 금지.

## 데이터 · API

`admin_actions`(insert만), `review_queue`, `auto_checks`, `reports`, `risk_signals`, `orders`, `credit_ledger`(조정은 `adjust` 반대 행), `payouts`, 커스텀 액세스 토큰 훅(`admin` 클레임), `private.is_admin()`, `/admin/**`(MFA, noindex).

## 테스트 매핑

- pgTAP: `admin_actions` UPDATE·DELETE 거부, 관리자 아닌 사용자의 `review_queue` 접근 거부
- Playwright: admin 시드 사용자로 승인·반려 → 크리에이터 알림, 신고 결정 → 환불 예외 경로

## 열린 질문

- 관리자 MFA 방식(Supabase MFA TOTP)
- 제재 사다리 기준 수치
