# F3 결제·라이브러리 — PAY · LIB · ORD

> '열기 전 7일'을 DB 함수가 판정한다

- 화면 명세: [PAY](PAY.md) · [LIB](LIB.md) · [ORD](ORD.md)
- 의존 결정: D1, D6, D9 (`docs/decisions.md`)
- 우선순위: P0(빠지면 출시 불가) · P1(출시 후 4~8주) · P2(설계만 대비)
- 수용 기준은 Given → When → Then을 줄인 것이고, 와이어프레임 예외(EX)·시나리오(SCN)에 대응한다. 테스트 이름에 요구사항 ID를 넣는다.

> **MVP 범위 (무료 출시, 사업자등록 전)**: 결제·환불·구매 내역은 **유료 전환 단계**다. PAY·ORD 화면, F3-1·F3-2·F3-3·F3-4·F3-6·F3-7, 「열기 전 7일」 환불과 m:openConfirm·m:refund·m:receipt는 MVP에서 만들지 않는다(목표 주 「유료 전환」). MVP에 남는 것은 LIB와 무료 받기(`claim_free_recipe`), F3-5(확인 팝업 없이 원문 열기, `opened_at`은 통계용 기록만, D6), F3-8(업데이트). 아래 결제·환불 내용은 지우지 않고 유료 전환 때 그대로 쓴다.

## 문제

결제는 성공하면 바로 라이브러리로 이어지고, 환불은 열기 전이면 한 번에 끝나야 한다. 청약철회 뒤 3영업일 안에 환불하지 않아 시정명령을 받은 사례가 있다. 그래서 PG 취소는 큐에 쌓지 않고 즉시 부른다.

## 목표

- 이중 지급 0건
- 결제와 권리의 불일치 0건
- 환불 3영업일 안 100%

## 비목표

- 크레딧 결제(D3 때문에 금지)
- 부분 환불
- 가상계좌·계좌이체(현금영수증 의무 검토 전까지 카드·간편결제만)

| 아이템 | 필수 콘텐츠 |

## 데이터 · API

거래 묶음 테이블(`orders`, `refunds`, `entitlements`, `entitlement_version_history`, `coupons`, `coupon_redemptions`, `share_links`, `share_link_clicks`, `private.webhook_events`), RPC `get_checkout_quote`·`create_pending_order`·`claim_free_recipe`·`confirm_order_paid`·`refund_order`·`open_original`·`apply_update`, 라우트 `/api/webhooks/toss`·`/api/files/[versionId]`. 토스 웹훅 이벤트는 `PAYMENT_STATUS_CHANGED`와 `CANCEL_STATUS_CHANGED`. 2025년 2월 시행 다크패턴 규정에 첫 과태료가 나왔으므로 미리 체크된 선택지는 두지 않고 총액을 먼저 보여 준다.
