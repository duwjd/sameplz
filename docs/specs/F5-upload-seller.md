# F5 올리기·판매자 센터 — UP · SELL

> 자동 검사와 지급대행을 한 줄로 잇는다

- 화면 명세: [UP](UP.md) · [SELL](SELL.md)
- 의존 결정: D1, D2, D7, D9, D10 (`docs/decisions.md`)
- 우선순위: P0(빠지면 출시 불가) · P1(출시 후 4~8주) · P2(설계만 대비)
- 수용 기준은 Given → When → Then을 줄인 것이고, 와이어프레임 예외(EX)·시나리오(SCN)에 대응한다. 테스트 이름에 요구사항 ID를 넣는다.

> **MVP 범위 (무료 출시, 사업자등록 전)**: UP은 **무료 올리기만**(가격 입력·판매 분기·m:verify 없음, 결과물 1개 이상). SELL은 **「내 레시피」 관리**(목록·상태·조회수·다운로드·SAME 수, 공유 링크는 유입 수만 세고 수수료 없음)와 **「유료 판매 오픈 알림 신청」 대기 명단(F5-14)**만. 판매자 등록(F5-8)·정산(F5-9)·유입별 매출·쿠폰·포크 로열티·원천징수는 **유료 전환 단계**다. 의존 결정 D1·D2·D7·D9는 deferred. 아래 판매·정산 내용은 지우지 않고 유료 전환 때 그대로 쓴다.

## 문제

크리에이터는 무료 공유를 5분, 판매 등록을 30분 안에 끝낼 수 있어야 한다. 동시에 스킬은 이미 공급망 공격 경로다. ClawHub에서는 스킬 2,857개 중 341개가 악성이었고, Snyk가 검사한 스킬 3,984개 중 13.4%에 치명적 결함이 있었으며 악성 스킬의 91%는 프롬프트 인젝션을 함께 썼다. 대금은 면허 있는 PG의 지급대행으로만 판매자에게 간다.

## 목표

- 반려 없는 첫 등록
- 자동 검사의 높은 검출
- 수요일 지급의 정확성

## 비목표

- 스크립트 샌드박스 자동 실행(출시 때는 수동 심사)
- 해외 판매자
- 세금계산서 역발행 자동화

## 데이터 · API

`recipe_drafts`·`recipe_versions`·`auto_checks`·`review_queue`·`seller_profiles`·`seller_earnings`·`payouts`·`share_links`·`coupons`·`recipe_daily_stats`, 액션 `saveDraft`(디바운스)·`createSignedUpload`·`submitRecipe`·`registerSeller`·`createShareLink`·`createCoupon`·`stopRecipe`·`setRecipeVisibility`. 크론은 Vercel Cron 화요일 지급 배치와 `pg_cron` 일간 통계·보류 해제. 토스 지급대행 웹훅은 페이로드+타임스탬프 HMAC-SHA256으로 검증.

## 지표

- 첫 등록까지 걸린 시간
- 자동 검사 오탐률
- 사람 확인 2일 이내 처리율
- 30일 안 판매 1건 이상인 크리에이터 비율

## 열린 질문

- 지급대행 심사에 통신판매업 신고증이 필요한지(미확인)
- 사업소득 간이지급명세서 주기(세무사)
- 개인 판매자 주민등록번호 수집·암호화 보관(세무사 + 변호사)
