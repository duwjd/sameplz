# F7 계정·알림·정책 — MY · NOTI · PRF · ACC · GUIDE · 로그인

> 필수 알림과 탈퇴 게이트가 축이다

- 화면 명세: [MY](MY.md) · [NOTI](NOTI.md) · [PRF](PRF.md) · [ACC](ACC.md) · [GUIDE](GUIDE.md)
- 의존 결정: D3, D4, D5 (`docs/decisions.md`)
- 우선순위: P0(빠지면 출시 불가) · P1(출시 후 4~8주) · P2(설계만 대비)
- 수용 기준은 Given → When → Then을 줄인 것이고, 와이어프레임 예외(EX)·시나리오(SCN)에 대응한다. 테스트 이름에 요구사항 ID를 넣는다.

## 문제

로그인은 받기·좋아요·팔로우·올리기·실행 직전에 뜨고, 로그인한 뒤에는 하려던 일로 돌아가야 한다. 알림은 결제·환불·정산·사람 확인·판매 중지·신고 답변 6종을 끌 수 없다. 탈퇴는 정산 대기 금액이 있으면 막고, 주문·정산 기록은 5년간 분리 보관한다. 마케팅 수신 동의는 별도 항목, 기본 미체크로 받고, 2년마다 재확인하고, 동의·철회 결과를 14일 안에 알린다.

## 목표

- 로그인 뒤 하려던 일로 복귀
- 필수 알림 6종 보장
- 탈퇴 게이트와 보관 의무 준수

## 비목표

- 비밀번호 없는 다중 기기 관리
- 사용자 간 메시지

## 데이터 · API

`profiles`, `notifications`, `notification_settings`, `marketing_consents`, `consent_events`, `archive.*`, 비공개 채널 `user:{uid}`, 액션 `updateProfile`·`checkHandle`(레이트 리밋)·`markAllRead`·`setNotificationSetting`·`setMarketingConsent`·`linkIdentity`·`unlinkIdentity`·`withdrawAccount`. UX 카피는 해요체·능동형·긍정형, 부정 소식은 사실 → 이유 → 다음 할 일, "검증·인증·보장"은 금지어(전문 영역 배지만 예외).
