# PLAY · 플레이그라운드

- 경로: `/play`
- 와이어프레임: `docs/wireframe/sameplz-wireframe-v0.5.html` (key `play`), 인벤토리 `docs/wireframe/_context_wireframe_inventory.md`
- 기능 묶음: [F4](F4-playground-credits.md) — F4 플레이그라운드·크레딧 — PLAY · CRD
- 의존 결정: D3, D5, D6, D8 (`docs/decisions.md`) — open이면 해당 부분은 멈추고 묻는다

> **MVP 범위**: **월 무료 크레딧으로만 돈다**(가입 때와 매월 리셋 때 지급, 270C·하루 135C — D11·D17). 충전·크레딧 환불·체험 모드(PLAY-01의 체험, F4-6, F4-10)는 없다 — 전부 무료라 체험이 필요 없다(D6). 모드는 내 레시피·받은 무료 레시피·빈 프롬프트 3가지. 실행 전에 **계정 일일 한도·IP/기기 레이트 리밋(F4-16)**과 **전체 월 예산 킬 스위치(F4-15)**를 서버가 검사한다. 잔액이 모자라면 충전 창 대신 「이번 달 크레딧을 다 썼어요 · 다음 리셋 날짜」. **모더레이션(F4-7)·AI 고지·라벨(F4-9)·얼굴 동의(F4-8)는 그대로 유지.** 체험·충전 내용은 지우지 않고 유료 전환 때 쓴다.

## 목적

레시피의 [변수]가 입력 칸이 되고, 모델을 최대 3개 골라 나란히 비교한다(Replicate 방식).

## 아이템

- **PLAY-01** 레시피와 모드: 체험(안 받은 유료 레시피, 1회, 워터마크, 원문 비공개) / 내 레시피(원문 편집 가능) / 무료 레시피 / 빈 프롬프트.
- **PLAY-02** 입력: 레시피의 [변수]가 그대로 입력 칸이 된다. 예시로 채우기, 레퍼런스 올리기. 얼굴 사진을 쓰는 레시피는 동의 체크 필수.
- **PLAY-03** 모델 비교: 레시피에 적힌 도구 중 API가 있는 모델만 고를 수 있고, 최대 3개를 나란히 돌려 비교한다.
- **PLAY-04** 예상 크레딧: 모델 단가 × 장 수(크레딧, D17 — 원화 환산 없음). 실행 전 금액을 보여주고, 모자라면 충전 창.
- **PLAY-05** 결과 그리드: 실행 한 번이 한 줄, 모델이 한 칸. 결과에는 AI 생성 표시가 붙는다.
- **PLAY-06** 결과로 할 일: 저장, 비교에 고정, SAME 인증 올리기(받은 레시피만). 빈 프롬프트 결과는 “레시피로 올리기”로 이어진다.
- **PLAY-07** 크레딧: 가입 보너스와 충전 크레딧. 생성에만 쓰고 레시피 구매에는 못 쓴다.

### 필수 콘텐츠 (보고서 F 묶음에서)

- **PLAY-01**: 모드 안내 4종: 체험(안 받은 유료, 1회, 워터마크, 원문 비공개) / 내 레시피(원문 편집) / 무료 레시피 / 빈 프롬프트, 빈 프롬프트 시작 예시 3~5개
- **PLAY-02**: [변수] 입력 칸(크리에이터의 예시 입력으로 「예시로 채우기」), 레퍼런스 올리기, 얼굴 사진 동의 「본인 사진이거나 사진 속 인물의 동의를 받았어요 · 생성에만 쓰이고 학습에 쓰이지 않으며 N일 뒤 자동 삭제돼요」
- **PLAY-03 · 04**: 레시피 도구 중 API 있는 모델 목록과 단가, 예상 크레딧 = 단가 × 장 수, 실행 전 표시
- **PLAY-05 · 06**: 실행 한 줄 × 모델 한 칸, 모든 칸에 「AI 생성」 배지, 첫 실행 전 고지 팝업 "이 화면의 결과물은 생성형 AI로 만들었어요", 저장·비교 고정·SAME 인증(받은 레시피만)·「이 설정으로 레시피 올리기」
- **PLAY-07 · CRD-01~04**: 잔액(유료·보너스 나눔, 보너스 유효기간), 충전 팩 3종(5,000원=500C, 10,000원=1,050C, 30,000원=3,300C), 내역(충전·사용·반환·환불·소멸), 규칙(모델 오류 반환, 안전 필터 차감 없음, 유료분 환불, 레시피 구매 불가)

## 동작

- 레시피 선택을 바꾸면 그 레시피 모드로 다시 그림
- 예시로 채우기 · 레퍼런스 올리기
- 「만들기」 → 실행 기록 맨 위에 한 줄(모델마다 한 칸)
- 결과: 저장 · 비교에 고정 · SAME 인증(받은 레시피만)
- 빈 프롬프트 결과 → 「이 설정으로 레시피 올리기」

## 규칙 (rl)

- 모드 4가지: 체험(안 받은 유료 · 1회 · 워터마크 · 원문 비공개) / 내 레시피 / 무료 레시피 / 빈 프롬프트
- 예상 크레딧 = 모델 단가 × 장 수(원화 환산 없음, D17)
- 크레딧으로 레시피는 못 삼
- 모델 오류는 크레딧 반환 · 안전 필터는 차감 없음

## 경우의 수 (c)

- 크레딧 부족: 모자란 만큼 보여 주는 충전 창 → 충전 뒤 다시 실행
- 체험을 이미 씀: 실행 버튼 꺼짐 + 「SAME 하고 계속 만들기」 → 결제 → 여기로 복귀
- API 없는 도구: 실행 불가 + 무료 레시피로 해 보기
- 얼굴 사진 레시피: 사용 동의 필수
- 에이전트·스킬: 2단계 안내 화면

## 예외 (EX)

- [ ] 체험을 이미 씀
- [ ] 크레딧 부족 → 충전 창

- [ ] 변수를 비우고 만들기

- [ ] API 없는 도구

- [ ] 만들기 중 서버 오류
- [ ] 연결 끊김 · 만들기 멈춤

## 데이터 · API

`credit_*`·`play_*` 테이블, RPC `start_run`·`place_hold`·`settle_cell`·`grant_purchase`·`request_paid_refund`·`expire_bonus`, 라우트 `POST /api/play/runs`·`POST /api/webhooks/generation/[provider]`·`/api/cron/play-sweeper`, 비공개 채널 `run:{run_id}`. 크레딧 설계는 로트별 행, 한 트랜잭션 안의 잔액 감소와 원장 기록, `FOR UPDATE` 직렬화, 멱등 키, 무료 크레딧 먼저 쓰기. 단가는 `크레딧 ≈ 공급자 USD × 1,450 × 1.8 ÷ 8.75 ÷ 0.37 ≈ USD × 805`(D17, 올림)(`.claude/skills/generation-pipeline/models.md`). 실패 처리 24행은 `.claude/skills/generation-pipeline/failure-matrix.md`.
