# SAMEPLZ 와이어프레임 v0.5 화면 인벤토리 (wf5-b.js NOTES에서 추출)

각 화면: d=한 줄 설명, a=동작, rl=규칙, c=예외·경우의 수, items=화면 요소(기획서 번호 순)

## 홈 (HOME, key: home)
- d: 구경이 먼저인 첫 화면. 롤링 배너 아래로 이번 주 다운로드 많은 → 실시간 인기 TOP 10 → 지금 뜨는 결과물 → 인기 크리에이터 순서.
- a:
  - 배너는 5초마다 넘어가고, 마우스를 올리거나 배너 안에 포커스가 있으면 멈춤
  - 배너의 멈춤·이전·다음·번호 버튼으로 직접 넘기면 자동 넘김이 꺼짐
  - TOP 10은 가로로 넘기는 순위 카드 · 탭을 바꾸면 순위만 다시 그림
  - 「전체 보기」 → 마켓 전체(다운로드순)
  - 결과물의 「같은 걸로」 → 원본 레시피 상세
  - 팔로우는 로그인 뒤 하던 일로 이어짐
- rl:
  - 배너 4장: 서비스 소개 · 플레이그라운드 · 이번 주 컬렉션 · 크리에이터 모집
  - 움직임 줄이기를 켠 사람에겐 자동 넘김을 처음부터 멈춤(WCAG 2.2.2)
  - 순위·다운로드 TOP에는 판매 중인 레시피만 · 인기 점수 = 다운로드 + SAME×4 + 좋아요×0.5
  - 카테고리 입구 카드는 없음 · 카테고리는 GNB 마켓 메뉴에서
- c:
  - 비회원: GNB 오른쪽은 로그인 하나 · 팔로우·「판매 시작하기」는 로그인 창부터
  - 회원: GNB 오른쪽은 알림 · 크레딧 · 마이페이지
  - 모바일: 배너 이미지가 위, 글이 아래 · 순위는 손가락으로 넘김
- items:
  - HOME-01 롤링 배너: 4장이 5초마다 넘어간다. 멈춤·이전·다음 버튼과 번호 표시(1 / 4), 장마다 이름 버튼. 마우스를 올리거나 포커스가 들어오면 멈춘다.
  - HOME-02 이번 주 다운로드 많은: 최근 7일 받은 수 기준 4개. 무료 레시피도 섞어 처음 온 사람이 바로 받아 보게 한다.
  - HOME-03 실시간 인기 TOP 10: 목록 대신 큰 순위 숫자와 카드를 가로로 넘기는 띠. ▲▼로 1시간 전 대비 변동을 보여 “지금 뜨는 것”을 만든다.
  - HOME-04 지금 뜨는 결과물: 갤러리 미리보기. 결과물이 먼저, 레시피는 한 번 누르면 나온다.
  - HOME-05 인기 크리에이터: 팔로우하면 새 레시피 알림이 온다. 비회원이 누르면 로그인 창이 먼저 뜬다.
  - HOME-06 통신판매중개 고지: 법적 고지는 초기화면 푸터에 둔다(전자상거래법 제20조).

## 마켓 (MKT, key: browse)
- d: GNB 마켓 = 프롬프트·에이전트·스킬을 합친 목록. 하위 메뉴(프롬프트·에이전트·스킬·컬렉션)는 마켓에 마우스를 올리면 열린다.
- a:
  - GNB 마켓에 호버·포커스 → 하위 메뉴 · ▾ 버튼은 클릭·Enter로 열고 Esc로 닫음
  - 마켓 전체는 카테고리·직무·가격 필터, 하위 카테고리는 카테고리마다 다른 필터
  - 필터·가격·정렬은 결과만 다시 그림 · 적용된 필터 칩으로 하나씩 해제
  - 검색은 GNB 검색창 하나 · 검색하면 마켓 전체에서 찾음
- rl:
  - 화면 안에는 카테고리 카드·검색창 없음(GNB 하위 메뉴와 위치 표시로 대신)
  - 기본 정렬은 인기순
  - 판매 중지·사람 확인 중·비공개 레시피는 목록에 안 나옴
- c:
  - 하위 카테고리에서 0건 + 다른 데 있음: 「스킬에 1개 있어요」·「마켓 전체에 N개」 칩
  - 어디에도 없음: 인기 검색어 칩 + 필터 초기화
  - 모바일(호버 없음): GNB 아래 하위 메뉴 줄(전체·프롬프트·에이전트·스킬·컬렉션) · 필터는 접고 펼침
- items:
  - MKT-01 위치와 제목: 홈 / 마켓 / 프롬프트 경로, 카테고리 이름과 판매 중 개수. 카테고리 카드 대신 이 줄로 어디에 있는지 알려 준다.
  - MKT-02 카테고리별 필터: 마켓 전체: 카테고리·직무 / 프롬프트: 종류·직무·사용 도구·비율 / 에이전트: 직무·실행 환경·연동 서비스 / 스킬: 직무·사용 도구·결과 형식.
  - MKT-03 정렬: 기본은 인기순. 다운로드순·급상승·최신순으로 상위 쏠림을 줄인다.
  - MKT-04 적용된 필터: 칩으로 하나씩 해제. GNB에서 검색한 말도 칩으로 남는다.
  - MKT-05 결과와 0건: 0건이면 다른 카테고리 결과 수, 그것도 없으면 인기 검색어.

## 프롬프트 상세 (PRM, key: item-prompt)
- d: 결과물이 첫 화면. 본문은 가리고 변수만 보여 주며, 받기 전에는 플레이그라운드 체험 1회로 확인한다.
- a:
  - 주 버튼은 상태마다 하나: 안 받음 「SAME 하기」 · 무료 「무료로 SAME 하기」 · 받음 「라이브러리에서 열기」 · 내 레시피 「새 버전 올리기」
  - 「바로 만들어 보기」 → 플레이그라운드(안 받은 유료는 체험 1회)
  - 좋아요·팔로우·신고·요청은 로그인 뒤 이어서
  - 모바일은 아래에 SAME 바 고정
- rl:
  - 가격도 라이선스도 하나
  - 원문을 열기 전 7일 안에만 환불
  - 따라 만든 결과는 받은 사람만 올릴 수 있음
- c:
  - 공유 링크(?ref=)로 들어오면 「링크로 들어옴」 띠 → 결제에서 직접 유입 5%
  - API 없는 도구(Midjourney 전용)는 「바로 만들어 보기」를 끄고 이유 표시
  - 내 레시피가 사람 확인 중·반려·비공개면 상단 상태 띠
  - 판매 중지면 다른 사람에겐 대체 화면 · 없는 주소는 404
- items:
  - PRM-01 결과물 갤러리: 첫 화면은 결과물. 영상은 비율 그대로(9:16) 재생.
  - PRM-02 인기 지표: 다운로드·SAME·좋아요·업데이트일. 검증 배지 대신 “몇 명이 따라 했는지”.
  - PRM-03 사용 도구·설정: 같은 결과를 내는 데 필요한 값.
  - PRM-04 프롬프트 미리보기: 본문은 가리고 변수만. 받은 뒤 라이브러리나 플레이그라운드에서 연다.
  - PRM-05 따라 만든 결과: 받은 사람이 올린 SAME 인증. 받기 전에는 “SAME 한 뒤 올릴 수 있어요”.
  - PRM-06 SAME 하기 (상태별): 비회원 → 로그인 → 이어서 결제 / 이미 받음 → 라이브러리 / 내 레시피 → 편집 / 무료 → 바로 라이브러리.
  - PRM-07 바로 만들어 보기: 플레이그라운드로 연결. 안 받은 유료 레시피는 체험 1회(워터마크, 원문 비공개). API가 없는 도구는 실행 불가 안내.
  - PRM-08 상황 띠: 공유 링크로 들어왔을 때(직접 유입), 내 레시피가 검토 중·반려됐을 때만 나타난다.

## 에이전트 상세 (AGT, key: item-agent)
- d: 동작 단계가 첫 화면. 예시 실행 로그로 무엇을 하는지 보여 주고, 하는 일·안 하는 일을 쉬운 말로 적는다.
- a:
  - 「예시 실행 보기」는 실제로 돌린 기록을 한 줄씩 재생
  - SAME 하면 설정 파일과 설치 안내
  - 플레이그라운드 실행은 2단계(지금은 안내 화면)
- rl:
  - 에이전트는 모두 사람 확인 뒤 공개(외부 실행)
  - 실행 비용은 받은 사람 계정에서
  - 세무·법률은 검토 보조만 · 자격 증빙이 있을 때만 배지
- c:
  - 전문 영역(종합소득세): 상단 고지 띠 + 「세무사 검수」 배지
  - 내 에이전트가 사람 확인 중: 나에게만 보이고 상태 띠
  - 반려: 사유 + 「고쳐서 다시 제출」
- items:
  - AGT-01 동작 흐름: 입력부터 결과까지 단계를 박스로.
  - AGT-02 인기 지표: 다운로드·SAME·좋아요·업데이트일.
  - AGT-03 예시 실행: 실제로 돌린 로그를 재생. 실행은 받은 사람 계정에서, 비용도 그 계정에서.
  - AGT-04 실행 환경·연동: 실행 환경, 연결할 서비스, 받는 사람이 준비할 것.
  - AGT-05 하는 일·안 하는 일: 권한을 쉬운 말로. 외부 전송·자동 게시 여부.
  - AGT-06 SAME 하기 (상태별): 프롬프트 상세와 같은 규칙. 에이전트는 플레이그라운드 실행 대신 설치 안내로 이어진다.
  - AGT-07 전문 영역 고지: 세무·법률은 검토 보조만. 자격 증빙이 있을 때만 배지.
  - AGT-08 상황 띠: 링크로 들어옴 · 사람 확인 중 · 반려 같은 상태를 맨 위에.

## 스킬 상세 (SKL, key: item-skill)
- d: 호출 예시(대화 모양)가 첫 화면. 전후 비교와 도구별 설치 3단계, 설치 명령 복사.
- a:
  - 설치 안내의 도구 탭을 바꾸면 3단계 문구가 그 도구로 바뀜
  - 「복사」 → 클립보드(막히면 복사 창)
  - 파일 구성은 이름만, 본문은 받은 뒤
- rl:
  - 지침만 있는 스킬은 자동 검사 뒤 바로 공개
  - 스크립트가 있으면 샌드박스 실행 + 사람 확인(1~2일)
  - 체험 채팅은 2단계
- c:
  - 스크립트 있음: 「스크립트 있음 · 사람 확인 완료」 태그
  - 무료 스킬: 「무료로 SAME 하기」 → 바로 라이브러리
  - 이미 받음: 「라이브러리에서 열기」
- items:
  - SKL-01 이렇게 말하면 작동해요: 호출 예시를 대화 모양으로.
  - SKL-02 인기 지표: 다운로드·SAME·좋아요·업데이트일.
  - SKL-03 전후 비교: 넣은 것과 나온 것.
  - SKL-04 설치 안내: 도구별 3단계와 설치 명령(예시 문구).
  - SKL-05 파일 구성: SKILL.md와 참고 파일. 본문은 받은 뒤.
  - SKL-06 안전 검사: 작게 표시. 스크립트가 있으면 사람 확인.
  - SKL-07 SAME 하기 (상태별): 프롬프트 상세와 같은 규칙.
  - SKL-08 상황 띠: 링크로 들어옴 · 내 스킬 상태를 맨 위에.

## 판매 중지 레시피 (STOP, key: item-stopped)
- d: 링크로 들어와도 받기 버튼 없이 사유와 비슷한 레시피를 보여 준다.
- a:
  - 받은 사람: 「받은 버전 열기」 → 원문(계속 사용)
  - 안 받은 사람: 사유 + 비슷한 레시피
- rl:
  - 받은 버전은 판매가 멈춰도 계속 사용
  - 중지 사유가 설명과 다름에 해당하면 신고로 환불
- c:
  - 비회원·안 받은 회원: 받기 버튼 없음
  - 받은 회원: 「받은 버전 열기」 · 라이브러리
  - 만든 사람: 일반 상세 + 「판매 중지」 상태 띠
- items:
  - STOP-01 중지 안내: 사유와 함께 지금은 받을 수 없다고 알린다.
  - STOP-02 받은 사람 안내: 받은 버전은 계속 쓸 수 있다는 안내와 「받은 버전 열기」.
  - STOP-03 비슷한 레시피: 막힌 길에서 돌아갈 곳.

## 404 · 없는 주소 (NF, key: nf)
- d: 주소가 바뀌었거나 비공개·사람 확인 중인 레시피, 또는 없는 화면 주소.
- a:
  - 홈 · 프롬프트 보기 · 인기 레시피로 돌려보냄
  - 주소창에 아무 주소나 넣어도 이 화면(예: /r/zz99, /abc)
- c:
  - 비공개·사람 확인 중 레시피를 남이 열면 404와 같은 화면(있는지 없는지 알리지 않음)
- items:
  - NF-01 안내: 이유를 쉬운 말로, 홈과 탐색으로 가는 버튼.
  - NF-02 인기 레시피: 바로 구경할 거리.

## 플레이그라운드 (PLAY, key: play)
- d: 레시피의 [변수]가 입력 칸이 되고, 모델을 최대 3개 골라 나란히 비교한다(Replicate 방식).
- a:
  - 레시피 선택을 바꾸면 그 레시피 모드로 다시 그림
  - 예시로 채우기 · 레퍼런스 올리기
  - 「만들기」 → 실행 기록 맨 위에 한 줄(모델마다 한 칸)
  - 결과: 저장 · 비교에 고정 · SAME 인증(받은 레시피만)
  - 빈 프롬프트 결과 → 「이 설정으로 레시피 올리기」
- rl:
  - 모드 4가지: 체험(안 받은 유료 · 1회 · 워터마크 · 원문 비공개) / 내 레시피 / 무료 레시피 / 빈 프롬프트
  - 예상 크레딧 = 모델 단가 × 장 수 · 1크레딧 = 10원
  - 크레딧으로 레시피는 못 삼
  - 모델 오류는 크레딧 반환 · 안전 필터는 차감 없음
- c:
  - 크레딧 부족: 모자란 만큼 보여 주는 충전 창 → 충전 뒤 다시 실행
  - 체험을 이미 씀: 실행 버튼 꺼짐 + 「SAME 하고 계속 만들기」 → 결제 → 여기로 복귀
  - API 없는 도구: 실행 불가 + 무료 레시피로 해 보기
  - 얼굴 사진 레시피: 사용 동의 필수
  - 에이전트·스킬: 2단계 안내 화면
- items:
  - PLAY-01 레시피와 모드: 체험(안 받은 유료 레시피, 1회, 워터마크, 원문 비공개) / 내 레시피(원문 편집 가능) / 무료 레시피 / 빈 프롬프트.
  - PLAY-02 입력: 레시피의 [변수]가 그대로 입력 칸이 된다. 예시로 채우기, 레퍼런스 올리기. 얼굴 사진을 쓰는 레시피는 동의 체크 필수.
  - PLAY-03 모델 비교: 레시피에 적힌 도구 중 API가 있는 모델만 고를 수 있고, 최대 3개를 나란히 돌려 비교한다.
  - PLAY-04 예상 크레딧: 모델 단가 × 장 수. 1크레딧 = 10원. 실행 전 금액을 보여주고, 모자라면 충전 창.
  - PLAY-05 결과 그리드: 실행 한 번이 한 줄, 모델이 한 칸. 결과에는 AI 생성 표시가 붙는다.
  - PLAY-06 결과로 할 일: 저장, 비교에 고정, SAME 인증 올리기(받은 레시피만). 빈 프롬프트 결과는 “레시피로 올리기”로 이어진다.
  - PLAY-07 크레딧: 가입 보너스와 충전 크레딧. 생성에만 쓰고 레시피 구매에는 못 쓴다.

## 결제 (PAY, key: checkout)
- d: 주문 확인과 결제를 한 화면에서. 유입 경로(직접 5% · 마켓 15%)와 철회 제한 동의를 보여 준다.
- a:
  - 쿠폰 적용 → 할인과 「직접 유입」 표시
  - 필수 동의 2개를 모두 체크해야 결제 버튼이 켜짐
  - 결제 → 완료 단계 → 라이브러리 / 플레이그라운드(체험에서 왔으면 강조)
- rl:
  - 크리에이터 쿠폰은 그 크리에이터 레시피에만
  - 크레딧으로는 결제 불가
  - 통신판매중개 고지 · 판매자 본인인증 표시
- c:
  - 없는 쿠폰 코드와 다른 크리에이터 쿠폰을 나눠 안내
  - 카드 한도 초과: 「결제되지 않았어요」 + 다른 수단 · 버튼은 「다시 결제하기」
  - 결제창 닫음: 고른 내용 유지
  - 이미 받음 · 내 레시피 · 판매 중지: 결제를 막고 안내
  - 비회원: 로그인 뒤 결제로 돌아옴
- items:
  - PAY-01 단계 표시: 주문 확인 → 결제 → 완료.
  - PAY-02 쿠폰: 만든 크리에이터의 레시피에만 적용. 쿠폰을 쓰면 직접 유입으로 잡힌다.
  - PAY-03 필수 동의: 철회 제한 동의 없이는 결제 버튼이 비활성.
  - PAY-04 통신판매중개 고지: 거래 당사자가 아님을 결제 단계에서도 고지.
  - PAY-05 유입 표시: 공유 링크로 들어왔으면 “직접 유입(수수료 5%)”. 판매자 대시보드 숫자로 이어진다.

## 라이브러리 (LIB, key: library)
- d: 마이페이지의 하위 기능. 받은 레시피를 바로 쓰는 곳. 레시피마다 받은 버전에 고정되고, 상태에 따라 환불·신고 버튼이 갈린다.
- a:
  - 원문 열기·파일 받기: 처음엔 「열면 환불이 제한돼요」 확인 창
  - 만들어 보기 → 플레이그라운드(내 레시피 모드)
  - SAME 인증 올리기 → 갤러리 · SAME 수 +1 · 크리에이터 알림
  - 업데이트 → 그 줄만 새 버전으로
- rl:
  - 열기 전 7일 안: 환불 요청
  - 열어 본 뒤: 환불 대신 「설명과 달라요」 신고(3개월)
  - 판매 종료: 받은 버전은 계속 사용
- c:
  - 열기 전 · 기간 지남: 환불 버튼 없음
  - 업데이트가 여러 개면 줄마다 따로
  - 받은 게 없음: 갤러리 구경하기
  - 비회원: 로그인 안내 화면
- items:
  - LIB-01 업데이트 알림: 받은 버전에 고정. 변경 내역을 보고 업데이트를 고른다.
  - LIB-02 상태: 열기 전(환불 기한) / 열어 봄(환불 제한) / 판매 종료(받은 버전은 계속 사용).
  - LIB-03 쓰기: 원문 열기·파일 받기(처음엔 확인 창), 플레이그라운드에서 쓰기, 설치 안내, SAME 인증 올리기.
  - LIB-04 환불·신고: 열기 전 7일 안이면 환불 요청. 연 뒤에는 환불 대신 “설명과 달라요” 신고(3개월).

## 알림 (NOTI, key: notifs)
- d: 마이페이지 안의 알림 목록. GNB 알림 버튼도 여기로 온다. 놓친 변화를 모으는 곳. 누르면 해당 화면으로 가고, 이 화면을 보면 GNB 숫자가 사라진다.
- a:
  - 알림 누르기 → 해당 화면(라이브러리·판매자 센터·상세·갤러리)
  - 이 화면을 열면 모두 읽음 처리
- rl:
  - 계정마다 따로 쌓임
  - 다른 계정의 행동이 알림을 만듦(판매·SAME 인증·업데이트·사람 확인 결과)
- c:
  - 알림 없음: 빈 화면 안내
  - 비회원: 로그인 안내 화면
- items:
  - NOTI-01 알림 목록: 업데이트, 판매, SAME 인증, 사람 확인 결과, 신고 답변, 팔로우한 크리에이터 새 레시피.
  - NOTI-02 연결: 모든 알림은 해당 화면으로 바로 이어진다. 읽으면 GNB 숫자가 줄어든다.

## 판매자 센터 · 레시피 올리기 (UP, key: create)
- d: 마이페이지 > 판매자 센터 안의 「레시피 올리기」 탭. 카테고리 → 내용 → 결과물 → 공개·가격 → 검사의 5단계.
- a:
  - 단계 탭으로 오가기 · 「다음」은 그 단계 필수값을 확인
  - 프롬프트는 [대괄호]를 변수로 자동 인식
  - 플레이그라운드 결과 가져오기(실행 기록이 있을 때)
  - 검사 통과 → 공개 / 사람 확인 / 비공개 저장 → 내 레시피 상세로
- rl:
  - 무료 공유는 결과물 1개 · 판매는 3개 이상
  - 판매는 본인인증 · 정산 계좌 · 원천징수 동의가 먼저
  - 새 버전은 변경 내용 필수 · 카테고리 변경 불가
  - 에이전트·스크립트 스킬은 사람 확인 1~2일
- c:
  - 제목 없이 다음: 칸 아래 오류 + 포커스
  - 가격 1,000원 미만: 오류
  - 검사 실패(숨은 지시문·보이지 않는 문자·금지 표현·결과물 수): 「고치러 가기」
  - 쓰다 나감: 초안 저장 → 「이어서 / 새로 시작」
  - 반려된 레시피: 사유를 보여 주고 다시 제출
- items:
  - UP-01 5단계 올리기: 카테고리 → 내용 → 결과물 → 공개·가격 → 검사.
  - UP-02 카테고리 선택: 프롬프트(이미지·영상·텍스트)·스킬·에이전트.
  - UP-03 GPTs 가져오기: GPT 지침을 스킬 초안으로. 스킬일 때만.
  - UP-04 카테고리별 입력: 프롬프트: [변수]·설정·레퍼런스 / 스킬: SKILL.md·호출 예시 / 에이전트: 단계·연동.
  - UP-05 결과물: 무료 1개, 판매 3개 이상. 플레이그라운드 결과를 바로 가져올 수 있다.
  - UP-06 공개 범위·가격: 판매는 본인인증·정산 정보가 있어야 한다. 라이선스는 하나, 가격도 하나.
  - UP-07 자동 검사: 숨은 지시문·금지 표현·결과물 수. 스크립트나 외부 실행이 있으면 사람 확인(1~2일).
  - UP-08 초안·새 버전: 쓰다 나가면 초안이 남고, 돌아오면 이어서 쓸지 묻는다. 새 버전은 변경 내용이 필수.

## 갤러리 (GAL, key: feed)
- d: GNB 갤러리(이전 이름 피드). 원본 결과물과 따라 만든 SAME 인증이 섞여 올라오는 놀이터.
- a:
  - 「같은 걸로」 → 원본 레시피 상세
  - 「이걸로 만들기」 → 원작 정보를 담은 올리기(포크)
  - 「내 결과 올리기」 → 받은 레시피 중에서 골라 올림
- rl:
  - 포크한 레시피가 팔리면 원작자 로열티 10%
  - 플레이그라운드에서 만든 인증은 「여기서 생성」 표시
- c:
  - 포크 막힌 레시피: 「이걸로 만들기」 없음
  - 받은 레시피가 없으면 올리기 대신 안내
  - 비회원 좋아요·포크·올리기: 로그인 뒤 이어서
- items:
  - GAL-01 결과물 모음: 원본과 SAME 인증을 섞는다. 플레이그라운드에서 만든 인증은 “여기서 생성” 표시.
  - GAL-02 같은 걸로: 어떤 결과물이든 원본 레시피로 바로.
  - GAL-03 이걸로 만들기: 포크. 원작 정보를 담아 올리기로. 판매되면 원작자 로열티 10%.
  - GAL-04 내 결과 올리기: 받은 레시피 중에서 골라 올린다. 받은 게 없으면 갤러리 구경으로 안내.

## 판매자 센터 (SELL, key: seller)
- d: 마이페이지의 하위 기능. 반응을 보고 파는 곳으로 한눈에 보기 · 레시피 관리 · 레시피 올리기 · 공유 링크·쿠폰 · 정산 탭이 있다.
- a:
  - 기간 7 · 30 · 90일
  - 레시피 관리: 반려 → 사람 확인 중 → 비공개 → 판매 중 순서
  - 공유 링크 만들기 → 「지우로 이 링크 열기」로 직접 유입 구매 따라가기
  - 쿠폰 만들기 → 결제에서 적용
- rl:
  - 직접 유입 5% · 마켓 유입 15% · 포크는 원작자 10% 추가
  - 7일 보류 뒤 매주 수요일 지급 · 개인 3.3% 원천징수
  - 링크 클릭 뒤 7일 안 구매만 직접 유입 · 셀프 구매 제외
- c:
  - 판매 없음: 빈 화면 + 올리기
  - 정산 정보 없음: 본인인증 하기
  - 링크 이름 규칙 위반 · 이미 있는 링크 · 쿠폰 코드 중복: 칸 아래 오류
- items:
  - SELL-01 한눈에 보기: 매출·다운로드·SAME·마켓 유입 비중.
  - SELL-02 유입 경로별 매출: 직접 유입(5%)과 마켓 유입(15%).
  - SELL-03 상품 관리: 상태(판매 중·사람 확인 중·반려·비공개)와 새 버전.
  - SELL-04 공유 링크·쿠폰: 링크를 누르고 7일 안에 사면 직접 유입.
  - SELL-05 정산: 7일 보류 후 매주 수요일, PG 지급대행. 개인은 3.3% 원천징수.
  - SELL-06 판매 시작 전: 본인인증·정산 계좌·첫 레시피 체크리스트.

## 마이페이지 홈 (MY, key: my)
- d: GNB 오른쪽 마이페이지(아바타)로 들어온다. 내 정보 요약과 할 일을 모으고, 왼쪽 메뉴로 라이브러리·구매 내역·크레딧·알림·내 활동·판매자 센터·설정으로 간다.
- a:
  - 숫자 타일(받은 레시피·크레딧·좋아요·팔로잉·SAME 인증)을 누르면 해당 화면·탭으로
  - 업데이트 줄에서 바로 업데이트
  - 판매자 센터 카드: 판매 중이면 30일 숫자, 아니면 「레시피 올리기」

- rl:
  - 마이페이지 메뉴: 내 레시피(라이브러리·구매 내역·크레딧) · 활동(알림·SAME 인증·팔로잉) · 판매(판매자 센터) · 설정(프로필·계정·알림 설정)
  - 데스크톱은 왼쪽 메뉴, 모바일은 위쪽 가로 메뉴
- c:
  - 비회원이 /my 주소로 오면 로그인 안내 → 로그인 뒤 마이페이지
  - 새로 가입한 회원: 숫자는 0, 각 칸에 다음 할 일 안내
- items:
  - MY-01 프로필 요약: 닉네임·핸들·가입일·판매자 인증 상태·소개. 「프로필 편집」으로.

  - MY-03 업데이트가 있어요: 받은 버전보다 새 버전이 있는 레시피. 여기서 바로 업데이트.
  - MY-04 최근 받은 레시피: 최근 3개와 상태, 원문 열기.
  - MY-05 판매자 센터 카드: 판매 중이면 30일 매출·다운로드·SAME, 아니면 올리기 안내.
  - MY-06 최근 알림: 최근 3개. 전체는 알림 화면.
  - MY-07 마이페이지 메뉴: 모든 마이페이지 화면에 같은 메뉴. 라이브러리 업데이트 수와 안 읽은 알림 수를 붙인다.

## 구매 내역 (ORD, key: orders)
- d: 유료로 받은 레시피의 결제 기록. 영수증과 환불 상태를 본다.
- a:
  - 상태 필터: 전체 · 결제 완료 · 환불
  - 영수증 → 영수증 팝업(인쇄·PDF 저장)
  - 열기 전 7일 안이면 「환불 요청」 → 환불 팝업 → 이 줄이 「환불 완료」로
  - 결제하면 맨 위에 새 줄(주문번호·쿠폰·유입 경로)
- rl:
  - 무료 레시피는 구매 내역에 남지 않음
  - 크레딧 충전 내역은 크레딧 화면에
  - 통신판매중개 고지는 영수증에도
- c:
  - 결제한 게 없음: 빈 화면 + 마켓 둘러보기
  - 환불된 주문: 「환불 완료」 + 환불일
- items:
  - ORD-01 상태 필터: 전체 · 결제 완료 · 환불.
  - ORD-02 주문 줄: 결제일·주문번호·레시피·판매자·유입 경로·금액·결제 수단·상태.
  - ORD-03 영수증 · 환불: 영수증은 항상, 환불은 열기 전 7일 안에만.
  - ORD-04 안내: 카드 취소 기간, 연 뒤에는 신고로, 크레딧 내역은 따로.

## 크레딧 (CRD, key: credits)
- d: 플레이그라운드 생성에만 쓰는 크레딧의 잔액·충전·내역·환불. GNB의 크레딧 버튼이 여기로 온다.
- a:
  - 충전하기 · 팩별 「충전」 → 충전 팝업
  - 내역 필터: 전체 · 충전·반환 · 사용·환불
  - 플레이그라운드에서 만들면 「사용」 줄이 쌓이고, 모델 오류면 「반환」 줄이 붙음
  - 충전 크레딧 환불 → 환불 팝업
- rl:
  - 1크레딧 = 10원 · 보너스 크레딧을 먼저 씀 · 보너스는 환불 안 됨
  - 레시피 구매에는 못 씀
  - 안 쓴 충전 크레딧은 환불(수수료는 약관)
- c:
  - 충전 크레딧이 없음(보너스만): 환불 버튼 꺼짐 + 이유
  - 내역이 없음: 빈 화면 안내
- items:
  - CRD-01 보유 크레딧: 잔액과 충전·보너스 나눔, 보너스 유효기간.
  - CRD-02 충전하기: 팩 3종과 단가 안내.
  - CRD-03 내역: 날짜·내용·증감·잔액. 충전·사용·반환·환불.
  - CRD-04 오류와 환불 규칙: 모델 오류는 반환, 안전 필터는 차감 없음, 충전분 환불.

## SAME 인증 · 팔로잉 (ACTV, key: activity)
- d: 내가 올린 SAME 인증, 팔로우한 크리에이터, 신고 내역을 모은 활동 화면.
- a:
  - 탭: SAME 인증 · 팔로잉 · 신고
  - 인증 「내리기」 → 갤러리에서 빠지고 레시피 SAME 수 -1
  - 팔로잉 「레시피 보기」 → 마켓에서 그 크리에이터로 검색 · 「팔로잉」 → 팔로우 끊기
- rl:
  - 신고 첫 답 1영업일 · 상태는 답변 대기 → 답변 완료
- c:
  - 올린 인증·팔로잉·신고가 없으면 탭마다 다음 할 일 안내
- items:
  - ACTV-01 탭: SAME 인증 · 팔로잉 · 신고.
  - ACTV-02 내 SAME 인증: 갤러리에 올린 결과. 내릴 수 있다.
  - ACTV-03 팔로잉: 팔로우한 크리에이터와 판매 중 레시피 수.
  - ACTV-04 신고 내역: 접수일·사유·상태.

## 프로필 (PRF, key: profile)
- d: 닉네임·핸들·소개·대표 직무·프로필 사진. 레시피 상세와 갤러리에 보이는 정보.
- a:
  - 고치면 「저장」이 켜지고 「저장하지 않은 변경이 있어요」 표시
  - 핸들 「중복 확인」 · 저장할 때도 다시 확인
  - 저장 → GNB 이름, 내 레시피 상세의 크리에이터 이름, 갤러리 인증에 바로 반영
- rl:
  - 닉네임 2~12자 · 핸들 영문 소문자·숫자·밑줄 3~15자 · 소개 60자 · 대표 직무 2개까지 · 사진 5MB 이하
  - 이메일은 공개하지 않음
- c:
  - 닉네임 길이 오류 · 핸들 형식 오류 · 이미 쓰는 핸들: 칸 아래 오류 + 포커스
  - 직무 3개째: 칸 아래 오류
  - 서버 오류: 입력값 유지
- items:
  - PRF-01 프로필 사진: 올리기 · 기본 이미지로.
  - PRF-02 닉네임 · 핸들: 필수. 핸들은 중복 확인.
  - PRF-03 소개: 60자, 글자 수 표시.
  - PRF-04 대표 직무: 2개까지. 추천에 쓴다.
  - PRF-05 저장 · 되돌리기: 변경이 있을 때만 켜진다.

## 계정 · 알림 설정 (ACC, key: account)
- d: 로그인 수단, 판매자 정보, 알림 설정, 로그아웃과 회원 탈퇴.
- a:
  - 로그인 수단 연결·해제
  - 판매자 정보 등록·정산 계좌 바꾸기 → 판매자 정보 팝업
  - 알림 스위치 → 해당 알림이 더 이상 오지 않음(업데이트·SAME 인증·팔로우)
  - 마케팅 수신 동의 → 동의일 기록
  - 회원 탈퇴 → 탈퇴 팝업
- rl:
  - 로그인 수단은 하나 이상 남아야 함
  - 필수 알림(결제·환불·정산·사람 확인·판매 중지·신고 답변)은 끌 수 없음
  - 정산 대기 금액이 있으면 탈퇴 불가
- c:
  - 마지막 로그인 수단 해제: 막고 안내
  - 정산 대기(크리에이터): 탈퇴 버튼 꺼짐
  - 탈퇴하면 받은 레시피·크레딧 소멸, SAME 인증은 「탈퇴한 회원」으로 남음
- items:
  - ACC-01 로그인 수단: 카카오·네이버·구글 연결 상태와 이메일.
  - ACC-02 판매자 정보: 본인인증·정산 계좌·원천징수 동의.
  - ACC-03 알림 설정: 필수는 항상 켜짐, 나머지는 끌 수 있음.
  - ACC-04 로그아웃 · 탈퇴: 탈퇴는 확인 팝업을 거친다.

## 로그인 (팝업) (-, key: m:login)
- d: 받기·좋아요·팔로우·올리기·실행 직전에 뜬다. 하려던 일을 기억했다가 로그인 뒤 바로 이어서 한다.
- a:
  - 카카오 · 네이버 · 구글 · 이메일 · 처음이면 자동 가입
  - 와이어프레임: 어느 버튼이든 지우로 로그인(로그인 만료 뒤에는 원래 계정)
- c:
  - 창을 닫으면 하려던 일 취소
  - 서버 오류: 창을 그대로 두고 다시 시도

## 신고하기 (팝업) (-, key: m:report)
- d: 열어 본 뒤 문제가 있을 때 환불 대신 쓰는 길.
- a:
  - 사유 4개 중 하나 + 내용 · 접수하면 알림
- rl:
  - 첫 답 1영업일
  - 설명과 다르면 크리에이터 소명 뒤 환불 결정(3개월 안)

## 원문 열기 확인 (팝업) (-, key: m:openConfirm)
- d: 처음 열 때만 뜬다. 열면 환불이 제한되고 연 시각이 기록된다.
- a:
  - 열기 → 원문 창 · 라이브러리 상태가 「열어 봄 · 환불 제한」으로
- c:
  - 두 번째부터는 바로 원문

## 원문 (팝업) (-, key: m:original)
- d: 받은 버전의 원문. 받은 사람 식별 정보가 들어 있다.
- a:
  - 프롬프트는 「플레이그라운드에서 쓰기」로 이어짐
- c:
  - 판매가 멈춘 레시피도 받은 버전은 열림

## 환불 요청 (팝업) (-, key: m:refund)
- d: 원문을 열기 전, 받은 지 7일 안에만 뜬다.
- a:
  - 신청 → 라이브러리에서 빠짐 · 크리에이터 매출 차감과 알림 · 상세에 다시 「SAME 하기」
- rl:
  - 전액 환불 · 카드 취소 3~5영업일
- c:
  - 서버 오류: 창을 그대로 두고 다시 시도

## 설치 안내 (팝업) (-, key: m:guide)
- d: 받은 레시피를 쓰는 도구별 3단계.
- a:
  - 프롬프트: 원문 복사 → 도구에 붙여넣기 → [대괄호] 바꾸기
  - 스킬·에이전트: 파일 받기 → 도구에 넣기 → 연결하고 실행

## SAME 인증 올리기 (팝업) (-, key: m:sameup)
- d: 따라 만든 결과를 갤러리에 올린다.
- a:
  - 올리기 → 갤러리 맨 위 · 레시피 SAME +1 · 크리에이터 알림 · 대시보드 SAME
- c:
  - 받은 레시피가 없으면 안내 창
  - 플레이그라운드에서 오면 결과를 그대로 · 「여기서 생성」 표시
  - 서버 오류: 창 유지

## 먼저 레시피를 받아 보세요 (팝업) (-, key: m:sameupEmpty)
- d: 받은 레시피가 하나도 없을 때 SAME 인증 대신 뜬다.
- a:
  - 갤러리 구경하기로 이어짐

## 크레딧 충전 (팝업) (-, key: m:charge)
- d: 플레이그라운드 생성에만 쓰는 크레딧을 충전한다. 실행하다 모자라면 모자란 만큼 위에 보여 준다.
- rl:
  - 5,000원 → 500C · 10,000원 → 1,050C(+5%) · 30,000원 → 3,300C(+10%)
  - 생성에만 쓰는 자체 크레딧 · 안 쓴 유료 크레딧은 환불
- c:
  - 서버 오류: 결제되지 않았다고 안내하고 창 유지

## 판매자 정보 등록 (팝업) (-, key: m:verify)
- d: 처음 판매를 고를 때 한 번만. 무료 공유·비공개는 없이도 올린다.
- a:
  - 휴대폰 본인인증 → 정산 은행·계좌 → 원천징수·지급대행 동의 → 등록 완료
- c:
  - 인증 없이 등록 · 계좌번호 8자리 미만 · 동의 안 함: 창 안에 오류

## 복사 (팝업) (-, key: m:copy)
- d: 클립보드가 막힌 환경에서 직접 골라 복사하도록 보여 준다.
- a:
  - 내용이 선택된 채로 열림

## 영수증 (팝업) (-, key: m:receipt)
- d: 구매 내역의 주문 한 건. 인쇄하거나 PDF로 저장한다.
- a:
  - 주문번호 · 결제일 · 상품 · 판매자 · 금액 · 쿠폰 · 결제 수단 · 상태
  - 「인쇄 · PDF 저장」
- rl:
  - 통신판매중개 고지 포함

## 충전 크레딧 환불 (팝업) (-, key: m:crRefund)
- d: 안 쓴 충전 크레딧을 결제 수단으로 돌려준다.
- a:
  - 환불 크레딧과 예상 금액 확인 → 환불 신청 → 크레딧 내역에 줄 · 알림
- rl:
  - 보너스 크레딧은 환불 안 됨 · 수수료는 약관
- c:
  - 서버 오류: 창 유지

## 회원 탈퇴 (팝업) (-, key: m:withdraw)
- d: 탈퇴하면 사라지는 것과 남는 것을 먼저 보여 주고, 막는 조건이 있으면 버튼을 끈다.
- a:
  - 떠나는 이유(선택) · 확인 체크(필수) → 탈퇴 → 비회원 홈
- rl:
  - 정산 대기 금액이 있으면 탈퇴 불가
  - 구매·정산 기록은 5년 보관
- c:
  - 확인 체크 안 함: 오류
  - 충전 크레딧이 남음: 「크레딧 환불 먼저」 버튼



# 화면별 예외 상황 목록 (wf5-b.js EX/EXL)

## home

- 검색 결과 없음 → 인기 검색어

- 검색 결과 없음 → 인기 검색어
- 이 탭엔 없고 다른 탭에 있음
- 필터를 겹쳐 0건
- 마켓 하위 메뉴 펼침 (호버 상태)
- 모바일 · 호버 대신 하위 메뉴 줄
- 모바일 · 필터 접힘

## my
- 비회원이 /my 주소로
- 새로 가입한 회원 · 빈 마이페이지
- 업데이트가 있는 레시피
- 로그아웃

## orders
- 결제한 레시피가 없음
- 환불된 주문만 보기
- 영수증 팝업
- 열기 전 주문 → 환불 요청

## credits
- 충전 크레딧 환불
- 보너스만 있음 · 환불 버튼 꺼짐
- 사용 내역만 보기
- 환불 중 서버 오류

## activity
- 올린 인증이 없음
- 팔로잉 탭
- 신고 내역

## profile
- 닉네임 1자로 저장
- 이미 쓰는 핸들
- 핸들 형식 오류 (대문자·공백)
- 대표 직무 3개째
- 이름 바꾸면 내 레시피 상세에 반영
- 저장 중 서버 오류

## account
- 마지막 로그인 수단 해제
- 업데이트 알림 끄면 새 버전 알림이 안 옴
- 마케팅 수신 동의
- 정산 대기 중이라 탈퇴 막힘
- 확인 체크 없이 탈퇴
- 탈퇴 → 비회원 홈
- 로그아웃

## collection
- 마켓 하위 메뉴 펼침 (호버 상태)

## item-prompt
- 비회원이 SAME 하기 → 로그인
- 무료 레시피
- 이미 받은 레시피
- 내 레시피 (만든 사람)
- 체험을 이미 씀
- API 없는 도구 (Midjourney 전용)
- 공유 링크로 들어옴
- 판매 중지된 레시피

# 시나리오 (wf5-b.js SCN)
- 비회원으로 구경하다 SAME 하기 (guest): 로그인 없이 구경하고, 받으려는 순간 로그인 → 하려던 일로 바로 돌아오기.
- 유료 SAME · 쿠폰 · 원문 열기 (jiwoo): 상세 → 결제 → 라이브러리 → 원문까지 한 번에.
- 열기 전 환불 (jiwoo): 원문을 열기 전, 7일 안이면 바로 환불.
- 열어 본 뒤엔 환불 대신 신고 (jiwoo): 열어 본 레시피는 환불이 막히고 “설명과 달라요” 신고로 이어진다.
- SAME 인증이 갤러리로 (jiwoo): 따라 만든 결과를 올리면 갤러리·SAME 수·크리에이터 알림이 함께 바뀐다.
- 체험 → SAME → 충전 → 생성 → 인증 (jiwoo): 플레이그라운드 체험이 구매와 SAME 인증까지 이어지는 흐름.
- 첫 판매 등록 (본인인증) (jiwoo): 판매를 처음 고르면 본인인증·정산 정보를 받고, 올린 레시피가 바로 탐색에 뜬다.
- 갤러리에서 포크 → 무료 공유 (jiwoo): 원작 정보를 담아 올리고, 상세에 원작이 표시된다.
- 판매 중지된 레시피 (jiwoo): 링크로 들어와도 대체 화면, 받은 사람은 계속 쓸 수 있다.
- 검색 결과 없음 → 인기 검색어로 (guest): GNB에서 없는 걸 찾으면 마켓 전체 0건 화면에서 인기 검색어로 다시 찾는다.
- 마이페이지 한 바퀴 (jiwoo): GNB 마이페이지에서 구매 내역·크레딧·프로필을 거쳐 판매자 센터의 레시피 올리기까지.
- 회원 탈퇴 → 다시 가입 (jiwoo): 탈퇴 팝업에서 사라지는 것을 확인하고 탈퇴하면 비회원 홈으로, 다시 로그인하면 새 회원으로 시작.
